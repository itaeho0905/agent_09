## 폴더 구조

```
agent_09/
├── .claude/CLAUDE.md   프로젝트 지침 (이 파일)
├── research/           자료조사 결과 (.md)
└── report/             최종 보고서 (.pdf)
```

## 저장 규칙

- 자료조사 결과는 `research/`에 .md로 저장한다.
- 보고서는 `report/`에 저장한다. 루트에는 결과 파일을 두지 않는다.
- 파일 이름: `주제_종류_vN.확장자` (예: `허준_자료조사_v2.md`, `허준_보고서_v2.pdf`)

## 작업 규칙

### 1. todo list 선보고 (항상)
- 사용자가 프롬프트로 작업을 요청하면, 어떤 작업이든 실행 전에 관련 todo list를 먼저 작성해 보고한다.
- todo list에는 단계별 작업 내용, 생성·수정·삭제될 파일과 폴더, 변경 후 예상 구조를 포함한다.
- 결정이 필요한 사항(덮어쓰기, 삭제, 저장 위치 등)은 todo list와 함께 질문한다.

### 2. 승인 후 실행
- 사용자가 todo list를 읽고 명시적으로 승인한 뒤에만 작업을 실행한다.
- 승인 전에는 파일 생성·수정·삭제 등 어떤 변경도 하지 않는다. (현재 상태 확인을 위한 읽기는 가능)
- 사용자가 todo list 수정을 요청하면 반영한 수정본을 다시 보고하고, 승인을 받은 뒤 진행한다.

### 3. 작업 마무리 시 구조 정리 (항상)
- 작업 중 폴더나 파일이 추가되었다면, 마무리 단계에서 Claude Code가 가장 잘 인식할 수 있는 구조로 정리한다.
  - 결과 파일은 용도에 맞는 폴더에 두고, 루트에는 두지 않는다.
  - 파일 이름은 `주제_종류_vN.확장자` 규칙에 맞춘다.
  - 새 폴더가 생기면 이 파일의 `## 폴더 구조`와 `## 저장 규칙`에 용도를 추가한다.
- 이 정리 단계는 처음 보고하는 todo list의 마지막 항목으로 항상 포함한다.

### 4. 기타
- 기존 파일을 덮어쓰지 않는다. 수정본은 버전 번호를 올려 새 파일로 만든다.
- 보고서는 서론, 본론, 결론 구성으로 작성한다.
- PDF 생성: 이 PC에는 Python이 없으므로 HTML로 작성한 뒤 Edge headless(`--print-to-pdf`)로 변환한다. 한글 글꼴은 맑은 고딕을 쓴다.
